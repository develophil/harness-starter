## 4. 사고 대응 — 중단과 되돌림

### 루프 폭주

1. 세션을 중단하고 백그라운드 작업과 작업 트리를 확인한다.
2. `.harness-state/stop-gate.count`는 내용을 기록한 뒤 제거한다.
3. 시작점과 현재 변경을 비교하고 필요한 파일만 선택해 원복한다.
4. 카운터, 턴 상한, 비용 감시가 작동하지 않은 원인을 `loops/` 변경안으로 남긴다.

### 유출 의심

1. 세션과 외부 전송을 중단하되 세션 로그는 보존한다.
2. 노출 가능 키는 조직 절차로 폐기하고 보안 담당자에게 알린다.
3. 커밋 이력 처리는 보안 담당자와 결정한다.
4. 놓친 경로를 훅과 무시 목록의 회귀 사례로 추가한다.

### 훅 오작동

1. 정상 작업 차단인지 위험 작업 통과인지 재현 입력과 종료 코드를 보존한다.
2. 해당 훅을 일시적으로 항상 성공하는 검토된 스텁으로 바꾸거나 기능 플래그를 끈다. Claude 훅은 설정 계층 간 병합되므로 전부 끄려면 `.claude/settings.local.json`에 `{"disableAllHooks": true}`(managed 훅 제외), Codex는 `features.hooks = false`. Codex 훅 스크립트를 고치면 `/hooks`에서 다시 신뢰 승인해야 실행된다.
3. 마지막 정상 설정으로 되돌린 뒤 재현 사례를 훅 테스트에 추가한다.
4. 로그를 삭제하지 않고 §7에 원인과 복구 시각을 기록한다.
